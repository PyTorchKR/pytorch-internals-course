# AI-slop 리뷰 지침 (읽기 전용 — 파일을 절대 수정하지 말 것)

## 대상과 목적
`/home/appleparan/src/pytorch-internal-lecture/.claude/worktrees/reduce-ai-slop` 의 한국어 PyTorch internals 강의 슬라이드(Astro + MDX)에서
"AI가 쓴 티(AI slop)"가 남은 곳을 찾고, 구체적인 대체 문안을 제안한다. 세 층을 모두 본다.

1. **표현(P)** — MDX 본문 산문, 헤딩, bullet, 표 셀, footnote.
2. **다이어그램(D)** — `<Mermaid>` 코드(노드/엣지 라벨, 구조, 장식), `public/images/NN/*.svg`의 텍스트 라벨, `<img>`/`<ThemeImage>`의 alt와 캡션 문장, 그림 바로 앞뒤 설명문.
3. **컴포넌트(C)** — 강의가 import하는 `src/components/*.astro`의 사용자에게 보이는 문구(단계 설명, 범례, 버튼, 헤딩, 툴팁, aria-label)와 시각 장식(이모지, pill/badge, 그라데이션, 과한 범례, 카드 3열 대칭 등).

## 이 프로젝트에서 "AI 티"로 확정된 패턴 (저자 피드백 — 최우선)
- 극적 프레이밍·서스펜스: "다만 공짜는 아닙니다", "이것이 바로 ~의 실체입니다", "진짜 이유는", "비밀은", "자연스러운 의문".
- 자기 서술형 전환: "가장 자연스러운 방법이", "~하는 셈입니다", "정리하면/결국/즉/바로/핵심은" 남발. 한 절에 "결국"이 두 번 이상이면 신호.
- 한 문장 안 (1)(2)(3) 인라인 나열, 헤지 접속 누적("결국 ~ 구조가 되고", "정작").
- 분열문·명사 결산: "핵심은 ~이다", "중요한 것은 ~", "문제는 ~라는 점이다".
- 영어 기술어의 음차(덴스, 트랜스포메이션, 인스트럭션) — 영어 원어 그대로 써야 함. (단 이미 정착된 한국어 번역어 "학습", "추론" 등은 그대로.)
- 저자가 원하는 문체: 사실을 먼저, 짧은 평서문, 문장당 한 생각, 은유·예고 없이 본론. 강의체 "-입니다/-합니다"는 유지.

## 다이어그램·컴포넌트에서의 AI 티 (시각 층)
- 노드 라벨이 문장이거나 설명문("~를 담당하는 계층")인 경우 → 명사구로.
- 본문 bullet을 그대로 박스로 옮긴 다이어그램(그림이 새 정보를 주지 않음) → 삭제 또는 관계가 드러나는 구조로 제안.
- 이모지 아이콘, ✓/✗ 리스트, 무의미한 색 강조(accent가 의미 없이 3색), "Step 1/2/3" 카드, pill 라벨, 범례가 그림보다 긴 경우.
- 캡션/alt가 "~를 보여주는 다이어그램", "~의 비교" 식 일반문 → 그림이 주장하는 사실 한 문장으로.
- 위젯 단계 설명문이 결산형("이것이 ~입니다", "~인 셈입니다")이거나 청자를 향한 과한 안내("~해 보세요!", 느낌표).
- 시퀀스/플로우에 실제 코드 식별자와 다른 임의 명칭.

## 하지 말 것
- 기술 사실의 정오는 이번 축이 아니다(이미 별도 리뷰로 반영 끝). 문안을 바꾸기 위해 사실을 바꿔야 한다면 그 사실을 flag만 하고 제안하지 않는다.
- 숫자·코드·식별자·고유명사·인용문·영어 약어는 건드리지 않는다.
- 강의자의 Q&A 기록, 원본 슬라이드 예제, 절별 요약표는 삭제 제안 금지(문장 다듬기만 가능).
- `docs/reviews/2026-09-05/<강의>.md`의 "반영 현황" 표에서 **미반영/부분 반영으로 저자가 보류한 항목은 다시 제기하지 않는다** (특히 01강). 먼저 그 표를 읽을 것.
- 이미 깨끗한 문장을 억지로 고치지 않는다. 과윤문은 실패다. 강의가 대체로 깨끗하면 그렇게 보고한다.
- MDX 문법 주의: 제안 문안에 `{ }`가 들어가면 `\{ \}`로 이스케이프. `<br />` 자기닫힘. 컴포넌트/코드블록 내부 문자열은 그대로 유효한 JS/HTML이어야 함.

## 산출물 형식 (지정된 경로에 마크다운 1개, 한국어)
```
# <강의 파일명> AI-slop 리뷰 (Opus)

## TL;DR (3~5줄)
전체 인상, 층별(P/D/C) 상태, 지배 패턴.

## 지배 패턴 (3~6개, 중요도 순)
- <패턴 ID/이름> — 어디에 몇 회쯤, 왜 티가 나는지, 일괄 처방 한 줄.

## 표현(P) 항목 — 중요도 순, 최대 40건
### P-01 [high|med|low] <파일>:<행>
- 원문: "<그대로 인용>"
- 문제: <패턴 ID> <한 줄>
- 제안: "<대체 전문 — 그대로 붙여 넣을 수 있는 완성 문장/블록>"

## 다이어그램(D) 항목
### D-01 [..] <파일>:<행> (Mermaid | svg 파일명 | alt/caption)
- 현재: ...
- 문제: ...
- 제안: Mermaid면 대체 코드 블록 전체 / svg면 바꿀 라벨 목록(old → new) / 캡션이면 대체 문장. 삭제 제안이면 근거.

## 컴포넌트(C) 항목
### C-01 [..] src/components/<파일>.astro:<행>
- 현재 / 문제 / 제안 (문자열 리터럴이면 따옴표·이스케이프 유지한 완성 형태로)

## 손대지 않아도 되는 것
이미 좋은 부분, 검토했지만 유지해야 할 이유가 있는 것(예: 강의자 Q&A).
```
행 번호는 반드시 실제 파일 기준. 인용은 축약 없이 그대로. 제안은 "이렇게 하면 좋겠다"가 아니라 대체 텍스트 자체.
