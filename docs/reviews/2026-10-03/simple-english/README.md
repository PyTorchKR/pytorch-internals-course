## TL;DR

- 강의 7편 모두에서 **가장 큰 문제는 "용어가 정의보다 먼저 나온다"(F)**이다. 7편 합계 66건으로, BLAS·autograd·FX graph(01), op(02, 148행에 나오고 729행에 정의), guard·graph break·IR(03), fake tensor·functionalization(04), CUDA stream·DTensor·device mesh(05), ridge point·SLO·MHA·GEMM(06), VLIW·warp·TMA(07)가 그렇다. 한 강의 안에서 정의 위치를 앞으로 당기거나 첫 등장에 10단어 괄호 정의를 붙이면 끝나는 일이다.
- 둘째는 **같은 개념의 표기 혼용(G)**이다. 강의마다 10~23쌍(graph/그래프, tensor/텐서, 하드웨어/hardware 등)이 섞여 있고, 07강은 684행을 경계로 한국어 표기에서 영어 표기로 통째로 바뀐다. 더 위험한 쪽은 **한 단어가 여러 뜻**으로 쓰이는 경우다. 05강 backend(통신 라이브러리 / rendezvous 구현 / Accelerate 병렬화 방식), 06강 block(tile / CUDA thread block / Triton 단위), 02강 "최하위"(229행은 libc, 553행은 #0 cuBLAS).
- 실습 절이 있는 02·04·05·06강에는 **지시문의 전제 누락(E)과 경고 순서(L)** 문제가 있다. 02강 빌드 전제(Python 3.10, gcc 11.3, 10GB)가 명령 블록 뒤에 나오고, 05강 torchrun 명령은 스크립트 배치와 포트 조건을 말하지 않으며, 04강 "다른 태그로 바꿔 실행"은 어느 명령의 어느 인자인지 말하지 않는다.
- 서식(I·K)은 강의당 25~30개 불릿이 "**용어** - 설명" 꼴이다. 오독 위험은 없지만 7편에 걸쳐 약 190행이라 기계적으로 한 번에 바꿀 수 있다.
- 문장 길이(A)는 양호하다. 중앙값 11~13어절이고 25어절 초과는 1~5%다. 세미콜론·이중피동·e.g./i.e.는 0건, 결산어는 09-27 패스 이후 거의 남지 않았다.

## 강의 전체에 걸친 패턴 (중요도 순)

1. **F SKILL 9: 정의 전 사용 66건.** 세 유형이다. (a) 정의가 뒤에 있음: 02강 op 148→729, 03강 FX Graph 24→452("여기서 처음 등장"이라고 썼지만 24행이 먼저), 05강 CUDA stream 552→780, 06강 ridge point 269→1020, 07강 VLIW 31→557. (b) 정의가 아예 없음: 02강 TunableOp·fallthrough key·Philox, 05강 agent·Elastic job·Ray actor·TP degree, 06강 SLO·MHA·SM·GEMM·SASS·MoE, 07강 GEMM·PC·in-flight·EPIC. (c) 지시 대상이 없음: 02강 162행 "회색 항목"(표는 취소선과 X로 표시), 597행 "그쪽", 01강 96행 "이를". 처방은 각 문서 항목에 대체 문안으로 있다.
2. **G 1.11: 표기 혼용과 다의어.** 혼용표는 각 문서 끝에 있다(01: 14쌍, 02: 21쌍, 03: 10쌍, 04: 12쌍, 05: 16쌍, 06: 23쌍, 07: 21쌍). 리뷰어는 "문서에서 먼저 쓴 표기"로 통일을 제안했지만, 한국어/영어 중 어느 쪽으로 갈지는 저자 결정이다. 다의어 세 건(05 backend, 06 block, 02 최하위)은 표기 선택과 무관하게 고쳐야 한다.
3. **E·L: 실습 절의 전제와 순서.** 02강 1416-1418행 빌드 전제를 명령 블록 앞으로, 1436행 cache 삭제 지시를 결과 설명 앞으로. 04강 1087-1090행 버전 재현 절은 어느 명령의 인자인지와 Python 버전 조건을 지시로 먼저. 05강 357행(스크립트 배치), 702·737행(process group 초기화 전제), 1112행(Ray cluster 전제), 629·684·848행(이유 뒤에 지시). 06강 470행(어떤 API로 Custom Op 등록), 974행(`--model-impl`이 어느 명령의 플래그인지), 863행("별도 build" 절차 없음).
4. **I·K: "**용어** - 설명" 불릿.** 강의당 25~30행. " - "는 두 진술의 관계를 숨기고, 볼드는 구조가 아니라 강조다. "용어: 설명." 꼴로 바꾸고 볼드를 뺀다. 01강 362-368행처럼 불릿 구조 자체가 보류 항목인 곳은 구두점만 바꾼다. 정의 목록 성격의 볼드 식별자 불릿(02강 424-428행 등)은 `code` 서식이 이미 항목을 표시하므로 볼드를 빼도 정보가 줄지 않지만, 슬라이드 원형 유지 여부는 저자 선택이다.
5. **A·B: 긴 문장과 다중 사실.** 집계는 아래 표. 25어절 초과 문장은 05강 FSDP 절(775~800), TP 절(906~938), 06강 223행(37어절), 07강 678행(약 50어절, 정의 4개)에 몰려 있다. 연결어미(-고/-며/-는데) 두 번 이상 사슬이 분리 기준이다.
6. **C·D: 피동과 헤지.** 이중피동은 0건. 남은 것은 행위자를 아는데 숨긴 피동("trace되어 캡처됩니다" → "TF2는 … trace하여 캡처합니다")과 "~하게 됩니다" 우회, 그리고 확정 사실에 붙은 "~할 수도 있습니다"(03강 5건, 07강 4건)이다.
