# 02-eager-mode.mdx Simple English 리뷰

## TL;DR (3~5줄)

본문 산문은 대체로 읽을 만하지만, 같은 개념에 여러 이름을 쓰는 G(1.11)가 가장 넓게 퍼져 있다(약 18쌍). 그다음은 용어를 정의보다 먼저 쓰는 F(SKILL 9)와 연결어미가 이어지는 긴 문장 A·B다. 문제가 몰린 곳은 dispatch 설명부(146-251행), `native_functions.yaml`·autograd kernel 설명(408-553행), 빌드 절차(1416-1436행)다. 빌드 절차에는 전제가 명령 뒤에 오는 E와 L도 있다. Runtime 절의 API 목록과 빌드 변수 표, Generated Files 절은 식별자 위주라 깨끗하다. 불릿의 " - " 스플라이스(I), 볼드 리드인(K), 명사 종결(N)은 슬라이드에서 온 패턴이라 건수는 많지만 low로만 묶었다.

## 지배 패턴 (3~5개, 중요도 순)

- G 1.11: 전역에서 18쌍 정도가 섞여 있다. tensor/텐서, memory/메모리, backend/백엔드, function pointer/함수 포인터, vtable/V-table/virtual table, backward graph/동적 계산 그래프, 코드 생성 도구/code generator가 그 예다. 553행 "최하위"는 229행과 call stack 방향이 반대다. 1231행 "장치"는 한국어로 device와 뜻이 겹친다. 같은 대상인지 독자가 매번 판단해야 하므로 오독 비용이 생긴다. 일괄 처방: 아래 혼용표의 첫 표기로 맞추고, 방향어는 "#0 쪽 = 위"로 고정한다.
- F SKILL 9: 11곳 정도에서 용어가 정의보다 먼저 나온다. op는 148행에 처음 나오는데 정의는 729행에 있다. structured kernel은 527행에 나오고 553행에서 정의된다. TunableOp, fallthrough key, Philox, shim, out-of-tree는 정의가 아예 없다. "회색 항목"(162행)과 "그쪽"(597행)은 가리키는 대상이 없거나 모호하다. 독자가 전제를 놓친 채 다음 단계를 읽게 된다. 일괄 처방: 첫 등장 위치에 10단어 이내의 괄호 정의를 넣는다.
- A 4.1·6.3 / B 6.1: dispatch 설명부의 서술문 17곳 정도가 문제다. 25어절을 넘거나, -며·-고·-는데·-므로가 두 번 이상 이어지거나, 한 문장에 사실을 둘 이상 담는다. 454행은 한 문단이 7문장이다(6.6). 일괄 처방: 연결어미에서 끊어 한 문장에 사실 하나만 둔다.
- E 5.4 / L SKILL 12: 빌드 절에 3건이 몰려 있다. 빌드 전제(Python·컴파일러·디스크)가 명령 블록 뒤에 온다. cache 삭제 지시는 결과 설명 뒤에 묻혀 있다. `-D`를 어디에 넘기는지도 빠져 있다. 따라 하는 독자가 실패한 뒤에야 전제를 알게 된다. 일괄 처방: 전제 목록을 명령 앞으로 옮기고, 조건과 지시를 먼저 쓴다.
- I·K·N (low): 불릿 30줄이 "항목 - 설명" 스플라이스를 쓴다. 볼드 리드인 52줄, 명사 종결 불릿은 Runtime·Build 절 대부분이다. 슬라이드에서 온 형식이라 오독은 적다. 처방: 스플라이스만 콜론으로 바꾸고, 볼드·명사 종결은 산문 문단에서만 고친다.
